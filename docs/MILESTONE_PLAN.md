Timeline assumes a single final-year student working part-time. Total ≈ 7 weeks.
Adjust the calendar, keep the order — each milestone consumes the previous one's output.

## Rules of the road

1. **Touch the test split exactly once.** All model selection uses the validation
   split. If you evaluate on test, tune, and evaluate again, your reported number is
   optimistically biased and an examiner is entitled to say so.
2. **One experiment = one folder** under `experiments/`, containing a snapshot of the
   config that produced it. Never overwrite a previous run.
3. **Never type a metric by hand.** Every number in the report is copied from a
   generated `metrics.json` or CSV. If a figure cannot be regenerated by a command,
   it does not go in the report.
4. **Commit after every milestone**, tagged `m1`, `m2`, … — the git history becomes
   the "project timeline" slide for free.

# Final demonstration deliverables

## A. Code and data artefacts
1. Git repository with the structure in `README.md`, tagged per milestone.
2. `requirements.txt` + `reports/environment.txt` (exact `pip freeze` of the machine used).
3. `configs/config.yaml` — every hyper-parameter in one reviewable file.
4. `data/splits/{train,val,test}.csv` — the exact split used (small, committed).
5. Best model checkpoint `experiments/<best_run>/best.pt` (+ how to obtain it if too large for git).
6. `experiments/<run>/metrics.json` for every run.
7. Populated SQLite database with a handful of real predictions and clearly-flagged
   simulated visit histories.
8. `pytest` suite, green.
